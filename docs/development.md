# Development & deployment

## Frontend

```sh
cd frontend && npm install && npm run dev
```

The dev server runs on port 8000 — the Cognito callback URL registered for local development.
`npm test` runs the Vitest suite.

Runtime configuration lives in `frontend/public/config.js`, generated by `deploy.sh`; for a manual
setup, copy `frontend/config.example.js` there.

`frontend/public/demo.html` is the walkthrough linked from the README, published beside the app at
`/demo.html`. It is self-contained rather than part of the bundle: it carries its own copy of the
screen and a snapshot of the questionnaire and recorded history matched to each other, because its
narration names specific carb grades and scores.

## Backend tests

`scripts/test.sh` runs the backend pytest suite.

## Deployment scripts (`scripts/`)

Copy `aws-config.example.sh` and `params.example.sh` to their gitignored siblings and fill them in
before running any script.

- `deploy.sh [env]` — packages and deploys both CloudFormation stacks (application and Cognito)
  and syncs the frontend. With an environment suffix (e.g. `dev`) it creates a fully isolated
  stack pair alongside the default one, including its own Cognito domain.
- `sync-frontend.sh [env]` — publishes the frontend alone, refusing a `config.js` built for a
  different environment.
- `delete-stack.sh [env]` — tears an environment down.

## Telegram (optional)

Store a bot token at SSM parameter `/diet-tracker/telegram/bot-token`, plus a per-user chat-id map
at `/diet-tracker/telegram/chat-map`. While the token parameter is absent, alert delivery is
email-only.
