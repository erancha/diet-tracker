# diet-tracker

Serverless Hebrew diet tracker built around an intraday meal log. Each meal is recorded as it
happens — carb grade plus whether it included vegetables — and scored in points (golf style:
lower is better). The day's values derive from the log: carb score, meal count, vegetable meals,
and the eating window between first and last meal. Recorded meals floor the end-of-day
questionnaire (a day can admit more than was tracked, never less), and a fully tracked day closes
from the tracker with only water entered. Proactive nudges run alongside: fill reminders while a
day is unsubmitted, threshold alerts over consecutive violating days (email, plus Telegram when a
bot token is configured), a weekly averages digest, and a 7-day trend chart after each submit.
Entries can be backfilled to yesterday for after-midnight logging.

**Stack**: Python 3.13 Lambdas behind an HTTP API (`/days` for history and submissions, `/meals`
for the intraday log) with Cognito Google sign-in gated by a small allowlist, three DynamoDB
tables (days / meals / nudge state), EventBridge Scheduler (Asia/Jerusalem), and a React
(TypeScript + Vite) RTL frontend served statically from S3 + CloudFront, charting with Recharts
and fetching through TanStack Query. Questions, their numeric choice values (the carb meal-point
weights among them), and the threshold alert rules are one versioned config:
`config/questionnaire.json`. Meal derivation is implemented once per runtime
(`src/common/derive.py` server-side as the authority, `frontend/src/derive.ts` client-side) and
both must satisfy the shared vectors in `config/derive-vectors.json`.

**Frontend dev**: `cd frontend && npm install && npm run dev` serves on port 8000 (the Cognito
callback URL registered for local development); `npm test` runs the Vitest suite. Runtime
configuration lives in `frontend/public/config.js`, generated by `deploy.sh` — copy
`frontend/config.example.js` there for a manual setup.

**Scripts** (`scripts/`): `deploy.sh [env]` packages and deploys both CloudFormation stacks and
syncs the frontend — with an environment suffix (e.g. `dev`) it creates a fully isolated stack
pair alongside the default one, including its own Cognito domain; `sync-frontend.sh [env]`
publishes the frontend alone, refusing a `config.js` built for a different environment;
`test.sh` runs the backend suite; `delete-stack.sh [env]` tears an environment down. Copy
`aws-config.example.sh` and `params.example.sh` to their gitignored siblings and fill them in.

Telegram is optional: store a bot token at SSM parameter `/diet-tracker/telegram/bot-token`
(plus a per-user chat-id map at `/diet-tracker/telegram/chat-map`); while the token parameter is
absent, delivery is email-only.
